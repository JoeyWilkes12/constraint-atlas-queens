02 / representations

Same semantics, different leverage.

A

Boolean grid

q[r,c] ∈ Bool

Contract: a cell is selected or not; all requested partitions are exact-one.

Trade-off: most transparent for audits and regional rules; 49 variables here, quadratic pairwise exclusions.

B

Integer per row

col[r] ∈ 0..6

Contract: each row chooses one column; distinctness captures columns.

Trade-off: compact for classical Queens; regions and conditional rules need element/lookup constraints.

C

Conflict graph

∀(u,v)∈E. xᵤ + xᵥ ≤ 1

Contract: vertices are choices; edges are incompatible pairs; partitions encode coverage.

Trade-off: makes sparse conflicts legible; loses row/column geometry without annotations.

03 / transfer lab

Translate the structure, not the chessboard.

Assignment

Variables: person × role choices. Partitions: each person and role. Conflicts: unavailable pairs or incompatible certifications. Objective: maximize fit or minimize cost.

Scheduling

Variables: job × time-slot choices. Partitions: each job and resource. Conflicts: overlap, setup, adjacency. Objective: minimize makespan or lateness.

Portfolio / mandate

Variables: mandate × instrument selections. Partitions: mandates, sleeves, exposure buckets. Conflicts: concentration and policy exclusions. Objective: maximize expected utility under limits.

Configuration / verification

Variables: component × setting choices. Partitions: required interfaces and zones. Conflicts: incompatible versions or safety rules. Objective: feasible configuration, then preferred cost/performance.

04 / solver context

How Z3 fits

Z3 is a general-purpose satisfiability modulo theories solver. In a Boolean encoding, a SAT-style engine proposes assignments and learns from conflicts; theory solvers add disciplined reasoning for domains such as arithmetic, arrays, and bit-vectors. CDCL(T) is the useful conceptual pipeline: encode a contract → search a Boolean skeleton → check theory consistency → learn a blocking explanation → return SAT with a model, UNSAT, or UNKNOWN. This page’s trace is deliberately a small transparent backtracker, not a reconstruction of that internal process.

05 / research ledger

Claims with a trail.

The LinkedIn Queens variant used here requires exactly one queen in every row, column, and coloured region, while forbidding queens in adjacent cells, including orthogonally and diagonally. Because the row and column equations already exclude orthogonal neighbors, only the 72 local diagonal pairs add nonredundant exclusions when both those rule families are active. Classical N-Queens instead forbids attacks across full diagonals.
